## 1. Стек и окружение

- **Агентная среда:** DeepSeek Harness (DSH) - локальная агентная среда с доступом к файловой системе, терминалу PowerShell и Unity CLI.
- **LLM-модель:** `gemini-3.8-flash-high` через `cliproxyapi`.
- **Системный контекст:** правила адаптированы из репозитория [TrueUnityAgent](https://github.com/wssdozh/TrueUnityAgent) (каталог `.agents/` и файл `AGENTS.md`):
  - Zero Junk: все файлы проекта только в `Assets/_Project/`.
  - Архитектура: единый Composition Root (`Bootstrap.cs`), без скрытых синглтонов и DI-контейнеров.
  - Состояние: Single State Owner у каждой модели.
  - Целостность: строгий контроль метафайлов и валидности YAML Unity.

## 2. Распределение задач

| Область | Что реализовал AI | Ручной контроль и доработки |
|---|---|---|
| **Доменная логика** | Модели `Wallet`, `MachineState`, `BoostState`, калькулятор офлайн-дохода | Исправлен алгоритм покадрового начисления: замена целочисленного округления на накопитель `_fractionalCoins` |
| **Unity IAP v5** | Изоляция через `IStoreService`, двухэтапный сценарий подтверждения в Fake Store | Переписан API: замена устаревшего IAP v4 (`IStoreListener`) на актуальный `StoreController` (v5.4.4) |
| **Аналитика** | Шина `AnalyticsService` и провайдер `DebugAnalyticsProvider` на 8 событий ТЗ | Проверка сигнатур и параметров событий |

| **Тестирование** | 10 EditMode тестов NUnit для проверки математики и транзакций | Проверка краевых условий и запуск через Test Runner |

## 3. Подход к постановке задач (Промптинг)

Задачи ставились итеративно, по слоям:
- **Пошаговая декомпозиция:** сначала чистые C#-модели без Unity API, затем сервисы (IAP, аналитика, сохранение), далее интеграция в `Bootstrap` и тесты.
- **Ограничения по сложности (YAGNI):** запрет создавать UI из кода скриптами, плодить промежуточные адаптеры и добавлять кастомные пункты в меню редактора.
- **Контроль версий библиотек:** сверка с установленным манифестом пакетов (`com.unity.purchasing` v5) перед генерацией кода.

## 4. Отклонённые предложения и исправленные ошибки

1. **Процедурная генерация UI через скрипты:** агент предлагал создавать Canvas и кнопки кодом при запуске. Отклонено: интерфейс собран статично в сцене `Main.unity` через стандартные компоненты uGUI.
2. **Скрипты автоматизации сборки и меню:** попытка добавить пункт меню Unity `MiniFactory` и отдельный C#-скрипт сборки отклонена. Сборка выполняется штатно через **File > Build Settings**.
3. **Устаревший API покупок:** модель сгенерировала код под `IStoreListener` (IAP v4). Логика переписана под актуальный `UnityIAPServices.StoreController()` (IAP v5.4.4).
4. **Потеря дохода при высоком FPS:** из-за формулы `(int)(rate * Time.deltaTime)` доход ниже 60 монет/сек обнулялся. Логика исправлена на накопитель дробной части.
5. **Повреждение сцены при правке YAML:** агент попытался вручную отредактировать `fileID` в файле сцены, вызвав переполнение `long.MaxValue`. Сцена восстановлена, привязка компонентов выполнена в редакторе.
6. **Ошибки устаревшего Profiler API Unity:** агент сгенерировал скрипт выгрузки метрик с устаревшим API Unity 2021/2022 (`ProfilerDriver.selectedFrame`, `SortModes`, `frameGCMemory`). Исправлено точечно под API Unity 6 (`ProfilerDriver.firstFrameIndex`, `columnTotalTime`, `columnGcMemory`, `GetItemChildren(List<int>)`).
7. **Устранение GC-аллокаций интерфейса:** в ходе профилирования реального файла захвата обнаружена покадровая аллокация строк (68 байт) в `WalletUI.OnCoinsChanged`. Заменена на безаллокационный `TextMeshPro.SetText("Coins: {0}", newCoins)`.
8. **Разблокировка 60 FPS на Android:** в профилировщике выявлен простой 10.9 мс в `WaitForTargetFPS` (Android по умолчанию лочит 30 FPS). В `Bootstrap.Awake()` задан `Application.targetFrameRate = 60;`.
